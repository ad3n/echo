Proxy response buffer pooling — 2026-10-31

Decision
Keep a single focused optimization: give httputil.ReverseProxy a shared,
fixed-size 32 KiB BufferPool. No other pool or zero-allocation change is justified
by this experiment. Baseline: 1039b64 (merged labstack/echo v5.4.4).
Production changes: middleware/proxy_buffer.go and one assignment in proxy.go.

Results (medians, 12 samples per variant per case)
Controlled proxy, 1 KiB response, GOMAXPROCS=4:
  Sequential: 4.080 us -> 1.955 us (-52.08%, p<0.001).
  Parallel:   3.653 us -> 0.8423 us/op (-76.94%, p<0.001).
Controlled proxy, 256 KiB response, GOMAXPROCS=4:
  Sequential: 8.629 us -> 6.735 us (-21.94%, p<0.001).
  Parallel:   5.192 us -> 2.095 us/op (-59.65%, p<0.001).
All eight controlled cases (CPU 1/4, serial/parallel, 1/256 KiB):
  Allocations: 32 -> 31 allocs/op.
  Allocated bytes: approximately 35.10 -> 3.10 KiB/op (-91%).
  Runtime improvement: 21.94–76.94%, all p<0.001.

Real HTTP, client -> frontend proxy -> upstream, GOMAXPROCS=4:
  1 KiB: 79.11 -> 77.33 us/op (-2.25%, p=0.001).
         45.40 -> 13.43 KiB/op (-70.43%); 160 -> 159 allocs/op.
  256 KiB: 153.9 -> 151.2 us/op (-1.74%, p=0.045).
           45.90 -> 13.89 KiB/op (-69.75%); 177 -> 176 allocs/op.
Treat the 256 KiB network latency difference as inconclusive at p<0.01.
Do not extrapolate the controlled throughput gains to network deployments.
All allocated-byte reductions in the network benchmark have p<0.001.

Method
Apple M3 Pro, darwin/arm64, Go 1.27.3.
benchstat: golang.org/x/perf v0.0.0-20261009192801-be2c69fb417e.
Two compiled test binaries, baseline and candidate, with equivalent benchmark
code. Each pair runs sequentially in a deterministically randomized order
(seed 20261031). Twelve independent process pairs, 250 ms calibration target
per case, benchmem enabled. No other tests or builds run concurrently with
measurement. Controlled cases use CPU=1,4; network cases CPU=4.
The first controlled binary predates whitespace-only benchmark formatting and
the addition of the separate network benchmark; its measured logic is identical.
Network binaries differ only in the proxy.BufferPool assignment.
Benchstat reports medians, 95% confidence intervals, and Mann-Whitney tests.
The conservative interpretation above uses p<0.01; this is not a preregistered
experiment or a correction for all possible comparisons.

Controlled transport removes socket scheduling and recreates the HTTP response
and body on every call. Each parallel worker owns its request and writer; the
Echo instance and balancer are shared. Output byte count is checked on every
operation. Real HTTP measures both TCP hops with keep-alive, fully consumes and
closes responses, checks status and byte count, and warms connections before
starting the timer. Setup is outside timing except one worker-local request and
writer setup per benchmark run, amortized over all iterations.
GC remains enabled. No CPU affinity/frequency lock or production workload is
claimed. These are steady-state, single-host throughput benchmarks, not tail
latency, cold-start, or RSS measurements. The primary evidence is the large,
repeatable reduction in allocated bytes, supported by timing results.

Ownership and memory tradeoff
ReverseProxy borrows one buffer for the synchronous body-copy operation and
returns it with its own defer, including copy-error/panic paths. HTTP upgrades
use the standard library's separate upgrade path. No request, context, response,
or transport object is pooled. Existing proxy identity hardening is unchanged.
The pool stores *[32768]byte, avoiding interface boxing of a slice on Put.
Warm buffer reuse removes this allocation, but the complete request still
allocates, and a cold/GC-evicted pool must allocate a replacement buffer.
Each retained item is exactly 32 KiB regardless of body size. Aggregate retained
memory is not hard-capped: it follows concurrency and sync.Pool/GC behavior.
Idle buffers can be discarded by GC. Buffer bytes are not zeroed; only bytes
actually read are written downstream. Readers/Writers must obey standard io
slice-ownership contracts. No unsafe conversion is used.

Validation
Full go test -race ./..., go vet ./..., and staticcheck ./... passed.
New tests exercise concurrent exclusive borrowing, response isolation at size
boundaries and large bodies, and body closure after upstream read failure.
Existing HTTP/WebSocket proxy identity and retry regressions also pass.
betteralign checked, applied, reviewed and checked again. Its 20 existing
layout diagnostics remain intentionally unchanged: unrelated/public struct
reordering is outside this optimization. No diagnostic targets the new pool.
